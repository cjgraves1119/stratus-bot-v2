## Rebuild evidence recorded on 2026-08-20 through 2026-08-21

The installed DEV artifact and the protected editable-source `dist/` contained
the same 35 files and 3,677,925 bytes. Their audited tree hash was
`8509f865e64dbc056d57804a9d5023d2ce4032a35404d14dbe9e66245dbd4a01`
under the reconciliation audit algorithm.

Installed source maps identified webpack `5.109.2` and Babel `7.29.7`, matching
`pnpm-lock.yaml`. Two clean `snapshot-dev` builds with Node `24.19.0`, pnpm
`11.19.0`, and the frozen pnpm lock each produced 35 files, 3,675,366 bytes,
and audit tree SHA-256
`482e2ad5fcda2d28df3c619e9e8bfd3475303814006544214cf8c7f63ea7b25f`.
The two builds matched each other byte-for-byte.

Compared with the installed evidence, 29 of 35 files matched byte-for-byte,
including every executable JavaScript bundle and the same chunk names. The six
explained differences were `manifest.json` plus five entry-bundle source maps.
The reconciled manifest is canonically serialized, removes the production
update URL and unrelated Worker origins from DEV, and the five maps embed the
reviewed `src/lib/constants.js` change that replaces implicit production API
and environment fallbacks with fail-closed named-target injection. The removed
npm lockfile described a different webpack/Babel dependency graph and is not
authoritative.

The reconciled release architecture intentionally changes the canonical root
manifest to production branding and removes the production auto-update URL from
both DEV targets. Therefore future safe DEV builds can differ from the historical
installed manifest even when application bundles remain lineage-equivalent.

## Commit-bound artifact provenance

This document records lineage; it is not a substitute for release provenance.
Every future production or team DEV package is generated by repository scripts
from a clean, exact reviewed commit/tag and includes:

- source commit and versioned tag;
- target and API origin;
- Node/pnpm versions and lockfile SHA-256;
- sanitized file inventory and tree SHA-256;
- package/CRX SHA-256 and a checksum manifest.

The team DEV gateway is not yet approved, so team packaging remains fail-closed.
No team package should be generated or published until that gateway and all
source/release gates are reviewed.
