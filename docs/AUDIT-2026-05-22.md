## ⚠️ CORRECTIONS (added 2026-05-22 after Round 1 verification)

This audit was produced by parallel sub-agents and **several findings were later
verified WRONG against the actual source**. Do not act on this audit without
re-verifying each finding. Confirmed corrections:

| Finding | Correction |
|---------|-----------|
| **CRIT-10** (`enrichCompanyV2` redefined inside `fetch()`) | **NOT A BUG.** `enrichCompanyV2` and the TTL constants are at module scope (worker-gchat lines 19505/19681, column 0). Nothing to fix. |
| **CRIT-12** (vision parse `slice(2)` off-by-one) | **NOT A BUG.** The synthetic block has two `\n---\n` separators → 3-part split → `slice(2)` correctly extracts the tail. The proposed `slice(1)` would be the regression. |
| **CRIT-2** (undo-token regex rejects valid tokens → crash) | **OVERSTATED.** Production tokens come from `crypto.randomUUID()` (8 hex chars); the existing `[a-f0-9]` regex already matches them. The base-36 path is a dead fallback. No crash occurs. |
| **CRIT-4** ("5 locations" need `Account_Name.id`) | **ONLY line 6094 is broken.** Sites 9112/9128/10752/10952 query the Accounts primary field or use legacy name-based lookup and are correct today — the proposed fix would break them. Fix line 6094 via COQL. |
| **CRIT-5** (5 double-write history sites) | **SITE LIST WRONG.** `askClaude` writes history only when it finishes without a `__continuation`; on continuation paths the endpoint/workflow writes are the *sole* writer. Removing them would lose history. Needs a proper per-path writer audit. |
| **CRIT-13** (add-pricing follow-ups "produce no pricing") | **MISCHARACTERIZED.** The live branch at webex:3279 already prices every term. The dead `if` block is redundant — the fix is to *delete* it, not resurrect it. |
| **CRIT-11** (proposed fix `env.ctx?.waitUntil(...)`) | **PROPOSED FIX IS A NO-OP.** `env.ctx` is never assigned in the Webex worker. The real fix needs `ctx` plumbing. |
| **CRIT-6** (`lastUserMsg.content` undefined deref) | **NOT A BUG.** Already guarded — worker-gchat:24948 is `lastUserMsg && detectCrmEmailIntent(lastUserMsg.content)`. The audit cited the wrong line (24940) and missed the existing short-circuit guard. |

See `docs/REMEDIATION-PLAN-2026-05-22.md` for the corrected, verified triage.

## PART 1 — CRITICAL BUGS

### 1.1 GChat Worker (`worker-gchat/src/index.js`)

#### CRIT-1: `generateUndoToken()` always returns full timestamp [line 1170]
```js
// BROKEN: substring() with negative arg treats it as 0 → returns FULL string
return 'u_' + Date.now().toString(36).substring(-8);
// FIX:
return 'u_' + Date.now().toString(36).slice(-8);
```
**Impact:** Every undo token is longer than intended. Downstream regex `^u_[a-f0-9]{4,}$` at line 12267 also rejects all valid base-36 tokens (see CRIT-2).

#### CRIT-2: Undo token regex rejects valid tokens [line 12267]
```js
// BROKEN: only matches hex [a-f0-9] but tokens are base-36 [0-9a-z]
const tokenShape = /^u_[a-f0-9]{4,}$/i;
// FIX:
const tokenShape = /^u_[0-9a-z]{4,}$/i;
```
**Impact:** Any token with characters g–z (common in base-36) fails the regex. Falls through to "undo last" path which crashes if `personId` is null.

#### CRIT-3: `eosLabel` ternary — both branches identical [line 2552]
```js
// BROKEN: both branches return 'End of Sale'
const eosLabel = eosDate <= now ? 'End of Sale' : 'End of Sale';
// FIX:
const eosLabel = eosDate <= now ? 'End of Sale (passed)' : 'End of Sale (upcoming)';
```
**Impact:** Past EOL dates and future EOL dates always display the same label. Users cannot tell if a product is already end-of-sale. (Same bug exists in Webex worker at line 2992.)

#### CRIT-4: `fetchPrimaryContactForAccount` wrong search API [line 6094]
```js
// BROKEN: Account_Name is a lookup field — :equals with accountId returns 0 results
`Contacts/search?criteria=(Account_Name:equals:${encodeURIComponent(accountId)})`
// FIX (use related-records endpoint or COQL):
`Contacts/search?criteria=(Account_Name.id:equals:${encodeURIComponent(accountId)})`
```
**Impact:** Primary contact resolution always fails silently. Every CRM operation that depends on primary contact falls back to placeholder or creates unnecessary contacts. (Same pattern at lines 9128, 10952.)

#### CRIT-5: Double history writes in CrmWorkflow [lines 16114–16115 + 16614–16615]
`askClaude()` internally calls `addToHistory()` for both user and assistant messages. Then `CrmWorkflow.run()` calls `addToHistory()` again for the same messages. Every workflow execution writes conversation history twice, corrupting context length and token counts for subsequent turns.

**Impact:** Conversation history grows at 2x the expected rate. Token budget calculations for prompt caching and history truncation are wrong.

Same double-write pattern confirmed at:
- `/api/chat`: lines 22161–22162 (after `askClaude` already wrote at 16114)
- `/api/chat-waterfall`: lines 22440–22441
- `/_work`: lines 24291–24292  
- `/_continue`: lines 24404–24405

#### CRIT-6: `lastUserMsg.content` dereference when history empty [line 24940–24949]
```js
const lastUserMsg = recentHistory.filter(m => m.role === 'user').slice(-2, -1)[0];
// NEXT LINE CRASHES if lastUserMsg is undefined (empty history / new session):
detectCrmEmailIntent(lastUserMsg.content)
```
**Impact:** `TypeError: Cannot read properties of undefined (reading 'content')` on new GChat sessions with no history.

#### CRIT-7: Queue consumer missing `__continuation` loop [lines 25480–25487]
`/_work` and `/api/handoff` correctly loop `while (result.__continuation)` to handle multi-step agentic workflows. The queue consumer calls `askClaude()` but has no continuation loop. If a queued CRM job returns `__continuation`, the consumer silently outputs `undefined` to GChat.

#### CRIT-8: `zoho_delete_record` no try/catch [lines ~13001–13272]
`zohoApiCall('DELETE', ...)` inside `zoho_delete_record` has no try/catch. Any Zoho API failure (network error, 403, timeout) throws an unhandled exception through the entire agentic loop.

#### CRIT-9: Hardcoded Anthropic API URL — bypasses AI Gateway [lines 19634, 23934]
```js
// BROKEN: Direct Anthropic call bypasses CF AI Gateway (no caching, rate-limiting, observability)
const resp = await fetch('https://api.anthropic.com/v1/messages', { ... });
// FIX: Use ANTHROPIC_API_URL constant already defined at line 22
await fetch(ANTHROPIC_API_URL, { ... });
```
Two locations: `callWebSearchEnrichment` (line 19634) and `/api/detect-account` handler (line 23934).

#### CRIT-10: `enrichCompanyV2` + TTL constants inside `fetch()` body
`const TTL_HIGH_CONFIDENCE = 30 * 86400` and `enrichCompanyV2` function defined inside `fetch()` handler body. Redefined on every request — cannot be garbage collected between warm requests. **Fix:** Hoist to module scope.

#### CRIT-11: `logBotUsageToD1` not in `ctx.waitUntil` [lines 7773–7781]

**Impact:** Cost tracking (`cost_usd`, token counts) silently dropped whenever the worker response completes before the D1 write.

```js
// Format: "LICENSE_DASHBOARD_PARSE_V1\n---\n{sku lines}\n---{tail}"
// BROKEN: split on \n---\n produces 2 parts for single-separator responses; slice(2) = []

// FIX:
cfVision.response.split(/\n---\n/).slice(1)
```
**Impact:** `EXPIRATION`, `MX_EDITION`, `MR_EDITION` metadata lost from parsed dashboard images.

#### CRIT-13: `handleFollowUpModifier` unreachable pricing branch [lines 3284–3288]
```js
const showPricing = isAddPricing;  // line 3274
if (isAddPricing && !showPricing) { // always false — showPricing === isAddPricing
  // Pricing fallback block — PERMANENTLY DEAD
}
```
**Impact:** Add-pricing follow-up requests that fail the primary path silently produce no pricing output.

#### CRIT-14: `logShadowClassification` runs 11 DDL statements per request [lines 1673–1754]
Runs `CREATE TABLE IF NOT EXISTS` + 10 `ALTER TABLE ADD COLUMN` statements on **every webhook request**. The `ensureTraceTable` pattern uses `globalThis.__traceTableReady` guard but `logShadowClassification` does not. At any meaningful request rate, this adds ~10 D1 DDL writes per request.

## PART 9 — CHROME EXTENSION BUGS

### Critical (will cause runtime failures or silent feature breakage)

**EXT-CRIT-1: `publishContext` clobbers message type [zoho-content.js:168]**
```js

```
**Impact:** Real-time Zoho page context updates never reach the background worker. The `MSG.ZOHO_CONTEXT_CHANGED` handler never fires. Sidebar shows stale Zoho data (falls back to 2-second storage polling).

**EXT-CRIT-2: Disconnect button does nothing [OptionsPage.jsx:145]**
```js
// BROKEN: raw string 'ZOHO_DISCONNECT' has no handler in background/index.js
sendToBackground('ZOHO_DISCONNECT')
// FIX: Add to MSG constants and register handler
[MSG.ZOHO_DISCONNECT]: async () => disconnectZoho()
```

**EXT-CRIT-3: `EMAIL_SENT` payload structure mismatch [background/index.js:201]**
Content script sends `{ type: MSG.EMAIL_SENT, data: { recipients, subject, sentAt } }`. After `registerMessageHandlers` strips `type`, handler receives `{ data: { ... } }` not `{ recipients, ... }`. All fields are `undefined`, early return fires, task-reschedule feature **never executes**.

**EXT-CRIT-4: Notification click `NAVIGATE_TO_TASKS` discarded [notifications.js:47]**
Background sends `{ type: 'NAVIGATE_TO_TASKS' }` to content script on notification click. Content script only handles `COPY_TO_CLIPBOARD` and `CRM_DATA_READY`. Clicking the "Tasks to Reschedule" notification does nothing.
